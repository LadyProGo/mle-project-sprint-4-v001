# Рекомендательная система для Яндекс Музыки

Проект по построению прототипа рекомендательной системы для музыкального сервиса Яндекс Музыки.

В первой части проекта выполнена подготовка и исследование данных, построены несколько типов офлайн-рекомендаций, обучена ранжирующая модель и проведена оценка качества рекомендаций.

# Подготовка виртуальной машины

## Склонируйте репозиторий

Склонируйте репозиторий проекта:

```bash
git clone https://github.com/LadyProGo/mle-project-sprint-4-v001.git
cd mle-project-sprint-4-v001
```

## Активируйте виртуальное окружение

Если виртуальное окружение ещё не создано, создайте его:

```bash
python3 -m venv env_recsys_start
```

Активируйте окружение:

```bash
. env_recsys_start/bin/activate
```

Установите необходимые зависимости:

```bash
pip install -r requirements.txt
```

## Скачайте файлы с данными

Для начала работы понадобятся три файла с исходными данными:

- `tracks.parquet`
- `catalog_names.parquet`
- `interactions.parquet`

Скачать их в директорию локального репозитория можно командами:

```bash
wget https://storage.yandexcloud.net/mle-data/ym/tracks.parquet
wget https://storage.yandexcloud.net/mle-data/ym/catalog_names.parquet
wget https://storage.yandexcloud.net/mle-data/ym/interactions.parquet
```

## Настройте доступ к S3

Для работы проекта необходим доступ к персональному S3-бакету.

Параметры подключения используются через переменные окружения из файла `.env`. Файл `.env` содержит секретные данные и не должен добавляться в Git.

# Расчёт рекомендаций

В ноутбуке `recommendations.ipynb` выполнены три этапа первой части проекта:

1. первичная подготовка и проверка данных;
2. EDA и подготовка данных;
3. построение и офлайн-оценка рекомендаций.

Данные были разделены по времени: в тренировочную выборку вошли взаимодействия до `2022-12-16`, не включая эту дату, а более поздние взаимодействия использовались как тестовые.

В проекте построены следующие типы рекомендаций:

- топ популярных треков;
- персональные рекомендации на основе ALS;
- рекомендации похожих треков item-to-item на основе ALS;
- итоговые персональные рекомендации после дополнительного ранжирования с помощью `CatBoostRanker`.

Для ранжирования использовались три признака:

- ALS-оценка рекомендации;
- исходный ранг рекомендации;
- популярность трека в тренировочных данных.

# Оценка качества рекомендаций

Качество трёх основных подходов оценивалось на контрольной группе из 1000 пользователей по метрикам `precision@10`, `recall@10`, `coverage@10` и `novelty@10`.

| Рекомендации | precision@10 | recall@10 | coverage@10 | novelty@10 |
|---|---:|---:|---:|---:|
| Топ популярных | 0.003000 | 0.003534 | 0.000010 | 11.198681 |
| Персональные ALS | 0.010100 | 0.014938 | 0.001001 | 12.251935 |
| Итоговые после ранжирования | 0.015200 | 0.019034 | 0.001880 | 12.840162 |

Итоговые рекомендации после ранжирования показали лучшие значения по всем четырём метрикам. Персональные ALS-рекомендации заняли второе место по качеству, а топ популярных показал наименьшие значения метрик.

Топ популярных можно использовать как простой базовый подход, ALS как основу персональной выдачи, а итоговый вариант после ранжирования как основной вариант формирования персональных рекомендаций.

# Ограничения прототипа

Цель проекта - построение рабочего прототипа рекомендательной системы. Из-за большого объёма исходных данных и доступных вычислительных ресурсов при построении прототипа использовалась сокращённая вычислительная схема:

- для этапа ранжирования и офлайн-оценки использована выборка из 5000 пользователей;
- 4000 пользователей использованы для обучения ранжирующей модели;
- 1000 пользователей использованы для контрольной оценки;
- кандидатный пул ALS ограничен 10000 наиболее популярными треками тренировочной выборки.

Такое ограничение позволило построить полный рабочий пайплайн без выполнения вычислений по всему каталогу. Поэтому полученные значения метрик следует интерпретировать как результаты прототипа на выбранной выборке, а не как окончательную оценку качества системы на полном наборе данных.
